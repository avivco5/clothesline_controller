# בקר מתלה כביסה מסתובב (Clothesline Controller)

בקר בטיחות ל-מתלה כביסה חיצוני מסתובב, המונע על ידי מנוע DC מוברש דרך חבל.
הבקר מזהה תקיעה של הכביסה (עלייה בזרם המנוע) ומנסה לשחרר אותה אוטומטית
על ידי היפוך כיוון זמני, ונועל את המנוע אם השחרור נכשל.

**פועל באופן אוטונומי לגמרי מהערכים הצרובים בקוד** — לא דורש חיבור, אפליקציה
או שרת חיצוני. בעליית מתח הוא מתחיל לנסוע קדימה לבד. נקודת הגישה של ה-Wi-Fi
וממשק האינטרנט (בעברית) עולים רק לחמש הדקות הראשונות אחרי כל אתחול, לצורך
כיוונון/בדיקה בלבד, ואז נכבים לגמרי — מאותו רגע הבקר פועל בלי שום רשת פעילה,
עד לאתחול הבא.

## חומרה

| רכיב | פרטים |
|---|---|
| בקר | NodeMCU v1.0 (ESP8266) |
| כונן מנוע | Pololu VNH5019 Motor Driver Carrier, #1451 |
| רגולטור 5V | SparkFun BabyBuck AP63357, COM-21256 |
| מנוע | DC מוברש, זרם רגיל ~2A, זרם תקיעה ~7A |
| הגנה | נתיך 10A בקו החיובי של אספקת המנוע |

זרם המנוע נמדד דרך יציאת ה-CS המובנית של ה-VNH5019 (כ-0.14V לאמפר) —
לא נעשה שימוש בחיישן ACS724 חיצוני שנרכש לפרויקט.

### חיווט

| VNH5019 | NodeMCU |
|---|---|
| VIN | אספקת מנוע (+), דרך נתיך 10A |
| GND | אספקת מנוע (−) + GND משותף |
| OUTA / OUTB | מנוע |
| VDD | 3V3 |
| PWM | D5 (GPIO14) |
| INA | D6 (GPIO12) |
| INB | D7 (GPIO13) |
| ENA/DIAGA | D1 (GPIO5) |
| ENB/DIAGB | D2 (GPIO4) |
| CS | A0 |
| CS_DIS | לא מחובר |

יציאת 5V של ה-BabyBuck מתחברת לפין VIN/5V של ה-NodeMCU — **אף פעם לא** ישירות ל-3V3.

**הנחות חומרה שלא אומתו במפורש ומצריכות בדיקה בפועל** (מפורט גם בראש `src/main.cpp`):
1. ENA/DIAGA ו-ENB/DIAGB הם פינים משולבים (הפעלה + דיווח תקלה). הקוד מגדיר
   אותם כ-`INPUT_PULLUP` כדי להחזיק אותם גבוה כברירת מחדל — יש לוודא עם מולטימטר
   שהם קוראים HIGH כשאין תקלה, ושהמנוע אכן מסתובב.
2. פין A0 של ה-NodeMCU קורא 0–3.3V דרך מחלק מתח שעל הלוח — מניח לוח v1.0 סטנדרטי.
3. `analogWrite()` ב-ESP8266 הוא PWM תוכנתי — תדר גבוה (10kHz) עם רזולוציה גבוהה
   הוא מגבלה ידועה של הליבה. יש לוודא עם אוסצילוסקופ שאות ה-PWM ואות ה-CS נקיים.

## תכונות

- **פועל אוטונומית מברירות המחדל הצרובות** — קדימה, 100% מהירות, בעליית מתח
- נקודת גישת Wi-Fi (`Clothesline-Control` / `clothesline`) בכתובת `http://192.168.4.1` — **פעילה 5 דקות בלבד אחרי כל אתחול**, ואז נכבית לגמרי (ראו "כיבוי Wi-Fi" למטה)
- ממשק אינטרנט בעברית (זמין רק ב-5 הדקות האלה): מהירות, קדימה/אחורה/עצור/שחרר נעילה, תצוגת זרם/מצב חיה
- הגנת עומס יתר: סף זרם + זמן טריגר, ניסיון שחרור אוטומטי (היפוך כיוון), נעילה (LOCKOUT) לאחר כישלון
- **ניסיון חוזר אוטומטי מ-LOCKOUT** — רק כשהנעילה נגרמה מעומס יתר שלא השתחרר (לא מתקלת חומרה), חוזר לנסות כל 30 דקות
- **הפעלה אוטומטית קדימה בעליית מתח** אחרי השהיה קצרה, רק אם אין תקלת אבחון — סטייה מכוונת מברירת המחדל הבטוחה, לפי בקשת בעל הפרויקט (ראו הערות בקוד)
- הגדרות הגנה ניתנות לכיוון מה-GUI ("הגדרות מתקדמות") בחלון ה-5 דקות — נשמרות ב-RAM בלבד, חוזרות לברירת המחדל הבטוחה בכל איתחול
- מכונת מצבים לא-חוסמת מבוססת `millis()`, ללא `delay()` בהפעלה רגילה
- זיהוי תקלת אבחון של ה-VNH5019 (DIAGA/DIAGB) בכל מחזור לולאה

## כיבוי Wi-Fi אחרי 5 דקות

ממשק ה-Wi-Fi/האינטרנט נועד לכיוונון והתאמת הערכים בלבד — לא לשליטה שוטפת.
לכן `WIFI_ON_DURATION_MS` (ברירת מחדל: 300000 מ"ש = 5 דקות) קובע חלון זמן
קצר אחרי כל אתחול שבו אפשר עוד להתחבר ולבדוק/לכוון; בתומו הבקר מכבה את
נקודת הגישה לגמרי (`WiFi.softAPdisconnect` + `WiFi.mode(WIFI_OFF)`) ורץ
משם והלאה **רק** לפי הערכים הצרובים, בלי שום רשת פעילה, עד לאתחול הבא.
מכונת המצבים של המנוע/ההגנה לא תלויה ב-Wi-Fi בכלל, כך שהכיבוי לא משפיע
עליה — רק חוסם גישה חיצונית.

כדי לכוון שוב, יש לאתחל את הלוח (כפתור RESET או ניתוק/חיבור חשמל) ולהתחבר
תוך 5 הדקות הראשונות.

## מבנה הפרויקט

```
platformio.ini      הגדרות בנייה (board = nodemcuv2)

release/             חבילת הפצה לצריבה על ידי מישהו אחר (ראו למטה)
```

## בנייה וצריבה

### אפשרות 1: PlatformIO (למפתחים)

```bash
cd Clothesline-Control
pio run                                    # קימפול בלבד
pio run -t upload --upload-port COM4       # קימפול + צריבה
pio device monitor --port COM4 --baud 115200   # צפייה בפלט הסיריאלי
```

### אפשרות 2: קובץ בינארי מוכן, בלי PlatformIO

בתיקיית [`release/`](release/) יש הכל: `firmware.bin`, `flash.bat`, `README.txt` (הוראות בעברית).
דורש רק פעם אחת: `pip install esptool`, ואז `flash.bat COMx`.
מיועד לשליחה למישהו אחר שרק צריך לצרוב, בלי שום סביבת פיתוח.

### אפשרות 3: צריבה מהדפדפן (Chrome/Edge, בלי שום התקנה)

`release/fw-data.js` מכיל את אותה קושחה כ-base64, מוטמעת בדף HTML עצמאי
(מפורסם כ-Claude Artifact) שצורב דרך Web Serial API באמצעות
`release/clothesline-flasher-bundle.min.js` — חבילה עצמאית שבנינו סביב
[esptool-js](https://github.com/espressif/esptool-js) (Transport + ESPLoader,
`writeFlash` בכתובת `0x0`, ללא manifest.json).

**למה לא [esp-web-tools](https://github.com/esphome/esp-web-tools) ישירות:**
נוסה קודם וכשל — ה-build שלו ב-CDN עושה `import` עם bare specifiers
(`"esptool-js"`, `"lit"`, `"@material/web/..."`, `"improv-wifi-serial-sdk"`)
שדפדפן לא יכול לפענח בלי import map/bundler, מה שגרם ל-custom element
לא לעלות בכלל ולהציג את כל תוכן ה-fallback גולמי. `esptool-js` לבדו תלוי רק
ב-`pako` וב-`atob-lite`, כך ש-`release/flasher-entry.js` יובא ונארז
(`esbuild --bundle`) לקובץ יחיד עצמאי לגמרי, בלי import map ובלי ספריות UI.

יש לבנות מחדש ולפרסם את הדף בכל פעם שהקושחה או ה-entry משתנים — הוא לא
מסתנכרן אוטומטית עם הריפו.

**חשוב:** לאחר כל שינוי בקוד, יש לעדכן את `release/firmware.bin` ו-`release/fw-data.js`:

```bash
cd Clothesline-Control
pio run
cp .pio/build/nodemcuv2/firmware.bin release/firmware.bin
{ printf 'const FW_BASE64 = "'; base64 -w0 release/firmware.bin; printf '";\n'; } > release/fw-data.js
```

ורק אם `release/flasher-entry.js` עצמו השתנה, לבנות מחדש גם את החבילה
(דורש Node.js; פעם ראשונה מתקינה תלות בתיקייה זמנית):

```bash
mkdir -p /tmp/flasher-build && cd /tmp/flasher-build
npm init -y && npm install esptool-js@0.7.0
cp /path/to/Clothesline-Control/release/flasher-entry.js .
npx esbuild flasher-entry.js --bundle --format=iife --platform=browser \
  --target=es2020 --minify --outfile=clothesline-flasher-bundle.min.js
cp clothesline-flasher-bundle.min.js /path/to/Clothesline-Control/release/
```

## כיוונון

כל הקבועים (פינים, סף זרם, זמנים, מהירות שחרור, פרטי Wi-Fi, פולריות כיוון) מרוכזים
בראש `src/main.cpp`. חלק מהם ניתנים לשינוי זמנית גם ללא צריבה מחדש, דרך פאנל
"הגדרות מתקדמות" בממשק האינטרנט **בחלון 5 הדקות** אחרי אתחול (נשמר ב-RAM
בלבד, מתאפס לברירת המחדל הצרובה למטה בכל הפעלה):

| הגדרה | ברירת מחדל | טווח |
|---|---|---|
| מהירות הפעלה אוטומטית | 100% | — |
| סף זרם עומס יתר | 3.0A | 1.5–9.0A |
| זמן עד טריגר עומס | 2.0 שנ' | 0.2–10.0 שנ' |
| זמן עצירה בין החלפת כיוון | 2.0 שנ' | 0.1–5.0 שנ' |
| משך היפוך שחרור | 15.0 שנ' | 0.5–15.0 שנ' |
| מהירות שחרור | 64% | 10–100% |
| מס' ניסיונות שחרור | 2 | 1–5 |
| זמן ריצה תקינה לאיפוס מונה | 60 שנ' | 5–600 שנ' |
| ניסיון חוזר אוטומטי מ-LOCKOUT (עומס בלבד) | 30 דק' | 0.5–30 דק' |
| חלון זמן Wi-Fi פעיל אחרי אתחול | 5 דק' | — (קבוע בקוד, לא דרך ה-GUI) |
